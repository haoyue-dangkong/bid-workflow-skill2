# 功能 2：根据目录生成文件夹和 DOCX

## 输入与边界

每次重新读取本次用户提供的 UTF-8 目录 TXT，不使用上一项目或上一轮记忆中的目录。只处理 `[文件夹]` 和 `[Word文件]` 节点；普通说明以及“依据和备注”之后的内容不创建文件。

## 阶段一：解析和预览

1. 检查 TXT 编码和内容。
2. 按两空格一级解析缩进、父子关系、类型、名称和顺序。
3. `[文件夹]` 生成文件夹；`[Word文件]` 生成 `.docx`。文件节点不能包含子节点，不能跳级。
4. 保留已有编号、顺序、括号、冒号、书名号和限定词，不补零、不重编号。
5. 文件名缺少 `.docx` 时只在预览中明确补充；已有 `.doc` 时转换为 `.docx`。文档内标题不包含扩展名。
6. Windows 禁止字符、空名称、保留名称、重复路径和不明确层级必须列为错误，不静默改名。
7. 输出完整预览树、预计文件夹数、预计 DOCX 数、被忽略说明和解析异常。

未收到用户针对当前完整预览明确回复“审核通过”之前，不创建、删除、重命名或覆盖实际文件。TXT 或预览发生变化后必须重新审核。

## 阶段二：审核后创建

1. 使用用户指定的独立输出根目录；不要写入 Skill 包或原始资料目录。
2. 按审核通过的节点原顺序创建文件夹和 DOCX。
3. 已存在的文件夹可复用并报告；任何同名文件默认是冲突，停止且不覆盖。
4. 每个 DOCX 只包含一个标题段落：标题等于文件名去掉扩展名，宋体、黑色、居中、12 磅；不添加“待编写”、正文区、目录状态或备注。
5. 写入失败时保留已成功创建的内容，分别报告成功、冲突和失败，不通过删除操作回滚用户资料。
6. 创建后重新扫描，核对文件夹层级、名称、数量、DOCX 可读性和标题内容。

## 可选脚本

```text
python scripts/parse_bid_tree.py 目录.txt
python scripts/create_bid_structure.py 目录.txt 输出目录
python scripts/create_bid_structure.py 目录.txt 输出目录 --approved
python scripts/check_bid_structure.py 目录.txt 输出目录
```

第二条命令没有 `--approved`，只预览不写入。脚本的批准参数不能替代用户在对话中的明确审批。

## 验收报告

报告输入 TXT、对应预览、审批状态、输出根目录、预期和实际文件夹数、预期和实际 DOCX 数、复用项、冲突项、失败项、标题错误和最终结论。
