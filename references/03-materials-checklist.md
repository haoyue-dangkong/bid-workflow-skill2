# 功能 3：生成编制投标文件所需资料清单

## 目标与边界

根据当前有效的招标文件、附件和补充文件，识别编制投标文件需要企业准备或确认的资料，形成可收集、可分工、可核对的“投标文件资料清单”。本功能不编写正文、报价，不判断企业资格，也不补造证件或数据。

## 输入

- 必需：招标文件 PDF 或可读取的 Word。
- 按项目补充：答疑、澄清、补遗、工程量清单、图纸、技术标准、合同附件、平台模板、已确认目录和企业资料包。
- 先确认输入是招标文件而非投标文件，并核对版本。没有企业资料包时只能说明“需要准备什么”，不能判断企业具体缺少什么。

## 三类资料

1. **企业现有证明资料**：营业执照、资质、安全生产许可证、人员证书、社保、业绩证明等，需要企业提供后才能核对。
2. **企业需要确认的信息**：不能直接从证件提取的报价、人员分工、工作经历、委托期限、是否填写业绩、现场踏勘等真实信息。
3. **可按模板编制的文件**：投标函、授权委托书、信誉或无拖欠等承诺。它们不是企业待提供的同名原始证明，但需要企业确认并依法签章。

## 生成规则

- 先识别当前招标文件要求，再列项；不按投标经验增加资料。
- 按商务标书、技术标书、资信标书及当前文件实际存在的其他部分分组。
- 同一资料在多处使用时合并成一项，列出全部用途和依据。
- 同一个人的资料合并为一条。例如项目经理的身份证、注册证、B 证、社保、学历、职称、无在建确认、简历和个人业绩均在“项目经理资料”下列细项。
- 项目经理、技术员、安全员等不同角色不能合并为一个人；只有招标文件明确要求的角色才列为必须。
- 营业执照已包含的企业名称、地址等，身份证已包含的姓名和号码，证书已包含的编号和有效期，不拆成独立“待提供资料”。需要填写但可从证件提取的字段也不重复索要。
- “若有”“如有”“可提供”“中标后”等条件必须保留。
- 只要求填写、签字或盖章的表格，列出表格名称和动作，不误列为企业原始证明。
- 正文、附件、答疑或补遗冲突时分别列出来源并标记“需确认最终要求”。

## 隐藏要求和补充询问

初稿后检查项目管理机构表、人员简历表、附件和评审办法是否出现正文未明确的信息，并集中询问用户：

- 是否需要技术员、安全员、施工员、质量员、材料员、劳务员等岗位；
- 每个岗位是否需要身份证、证书、学历、职称和社保；
- 简历是否需要毕业学校、工作经历和个人业绩；
- 个人业绩是否需要合同、竣工验收等证明；
- 业绩、荣誉、财务、信用是否只是条件性或定标参考资料。

每个问题引用具体页码、附件或表格，并说明答案影响哪些清单项。招标文件未明确时写“待确认”，不能擅自改成必须。

## 输出格式

内部至少记录：序号、投标文件部分、资料名称、用途/章节、动作、必须性、提供方、招标依据、状态和备注。

用户可见输出默认使用简明编号清单，不使用大表格；顺序为：

1. 商务标书资料；
2. 技术标书资料；
3. 资信标书资料；
4. 可直接编制、需企业确认签章的文件；
5. 待用户确认的问题。

每项写“资料名称 + 提供内容 + 必要限制条件 + 页内页码/附件依据”。复杂人员资料用一个总项加“（1）（2）”细项。用户明确要求时再增加责任人、截止时间和收集状态。

## 状态口径

- 已明确要求：正文、资格条款或附件明确写明。
- 条件性准备：条件触发时才需要。
- 可直接编制：有模板，企业确认事实并签章。
- 待确认：文件未明确必须性、人员范围、格式或条件。
- 未提供企业资料包：尚不能核对齐全性。
- 缺少数据：只有已经扫描用户提供的资料包、确认不存在对应材料或必要信息时使用。
