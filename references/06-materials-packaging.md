# 功能 6：根据资料清单整理项目资料包

## 目标与边界

根据功能 3 的最终《投标文件资料清单》，从企业全部资料中识别、匹配并整理本项目需要的原始资料副本。

本功能负责清点、候选匹配、风险/缺口识别、预览、审核后复制和索引；不编写投标正文，不修改/裁剪/合并原始资料，不判断企业一定满足资格，不靠文件名猜内容，也不补造缺失资料。

## 输入

- 必需：最终版资料清单、企业全部资料文件夹。
- 建议：项目名称、用户指定输出目录、投标目录、最终澄清补遗和已确认人员/项目/条件。
- 没有资料清单只能清点，不能声称按招标要求完成；没有企业资料只能报告需求和缺口；没有输出目录先扫描预览，不在未知位置写入。

## 状态

- **已匹配**：找到明确候选，但仍需检查有效期、签章和完整性。
- **多候选**：两个以上候选，不能擅自选择。
- **待确认**：人员、项目、版本、条件或归属需用户决定。
- **待复核**：候选已找到，但主体、期限、签章、页数或内容未核清。
- **缺少数据**：完整扫描后没有对应文件或必要信息。
- **条件未确认**：是否触发“若有/中标后”等条件尚不明确。
- **不适用**：招标文件或用户已确认条件不触发。
- **已确认**：用户确认当前对应关系；不替代资格和最终投标审核。

仅文件名相似、多个版本不明、主体/人员/项目不一致、期限或签章未核、同一人员只找到部分材料时，不能直接标“已匹配”。条件未确认时不能因未找到文件就标“缺少数据”。

## 工作流

### 1. 清点输入

读取本次清单和版本，递归登记企业资料的相对路径、原文件名、格式、大小和修改时间。尽量读取 PDF、Word、Excel、TXT 和图片内容；密码保护、损坏、模糊或无法读取的文件标“待复核”。压缩包默认作为一个原始文件，只有解压并重新扫描后才使用内部资料。

### 2. 建立对应关系

```text
资料清单项 → 候选企业文件 → 匹配证据 → 风险/缺口 → 当前状态
```

依次核对资料用途、企业主体、人员姓名/岗位、项目/合同、证书编号/类别/范围、有效期/注册状态/社保期间、签章/完整性/版本以及招标要求的格式和时间范围。

同一个文件可服务多个清单项，默认只复制一份并在索引列出全部用途；用户明确要求按分册复制时才复制多份并记录重复关系。同一人员在清单中是一个整体，匹配时也检查其全部细项。

### 3. 输出预览并等待审核

审核前只报告：清单总项、候选文件、多候选/版本冲突、主体/人员/项目/期限问题、缺少资料、条件待确认、未纳入清单的企业资料、建议目录和预计复制清单。此阶段不得复制、修改、移动或重命名企业资料。

只有用户针对当前预览明确回复“审核通过”或同等明确批准，才进入复制；“继续”“看看”或修改意见不算批准。

### 4. 复制和验收

1. 新建独立项目资料包，不覆盖原始资料。
2. 按商务、技术、资信和通用分类建目录，复制经确认的原始文件，默认保留文件名和格式。
3. 多来源/多版本均保留并在索引说明，不擅自合并或选择。
4. 未纳入清单的资料默认不复制，只列报告；用户要求全部备份时放入单独目录。
5. 重新扫描输出目录，核对文件数、名称、路径和复制结果。

## 建议目录与索引

```text
项目资料包/
├─ 00_索引与审核/
│  ├─ 资料包索引.md
│  ├─ 资料包整理报告.md
│  ├─ 待确认项.md
│  ├─ 缺少资料清单.md
│  └─ 未纳入资料清单的企业资料.md
├─ 01_商务标书/
├─ 02_技术标书/
├─ 03_资信标书/
└─ 04_通用资料/
```

索引至少记录：序号、投标部分、清单项、资料包相对路径、企业原始相对路径、匹配证据、状态、风险/缺口、招标依据和审核状态。Windows 禁止字符只可在复制副本的目录名中安全替换，并在索引记录原名。

## 完成报告

报告清单版本、企业资料输入目录、扫描数和无法读取项、各状态数量、实际复制清单和位置、多版本/重复/期限/签章/完整性风险、未纳入资料、原始资料未修改情况及下一步。

只有审核通过且复制核对完成后才可写“已整理完成”。仍有缺少、待确认或待复核时，应写“资料包已按当前确认范围整理，仍有未完成项”。
